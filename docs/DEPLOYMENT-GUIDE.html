2. rconfig 主機部屬步驟

A. 專案克隆與目錄準備

cd /opt
sudo git clone http://172.16.5.124/STW-Infrastructure/DEV-rconfig-fortigate-bridge.git
cd DEV-rconfig-fortigate-bridge

B. 環境變數設定

sudo cp .env.example .env
sudo nano .env
# 請填寫正確的 DB_USER, DB_PASSWORD, RCONFIG_DATA_PATH

C. 建立 SFTP 系統帳號 (極重要)

此帳號需與 Docker 映射同步，用於接收 Fortigate 的連線。

# 建立帳號（密碼請查閱 1Password）
sudo useradd -m -s /bin/bash rconfig_backup
sudo passwd rconfig_backup

# 建立暫存目錄與權限校準
sudo mkdir -p /opt/DEV-rconfig-fortigate-bridge/data/INCOMING_TEMP/upload
sudo chown -R rconfig_backup:rconfig_backup /opt/DEV-rconfig-fortigate-bridge/data/INCOMING_TEMP

D. 啟動服務

# 必須使用 Docker Compose V2
sudo docker compose up -d

3. Fortigate 設備端設定

路由設定 (指定 Source IP)

若設備有虛擬系統 (VDOM) 或多線路，必須指定 Source IP 才能連向 stwrconfig6。

config system sftp
    set preferred-source 10.x.x.x  # 該設備在公司內部的 IP
end

Automation Action 腳本

config system automation-action
    edit "Backup_To_rconfig"
        set action-type cli-script
        set script "execute backup config sftp upload/%%hostname%%-%%date%%.conf 172.16.5.124:2222 rconfig_backup [密碼]"
    next
end

4. 雷區預防與常見陷阱

雷區一：SFTP 絕對路徑問題

症狀：連線成功但上傳失敗 (Permission Denied)。

Fortigate 指令必須包含 upload/ 前綴，因為 Docker 映射只允許寫入該子目錄。

雷區二：Linux 系統帳號 UID 衝突

Docker 內的 rconfig_backup 預設 UID 為 1000。若 Linux 主機 UID 不符，Watcher 將無法讀取檔案。

雷區三：UFW 防火牆 3306

必須放行 Docker 橋接網段連向 3306 埠口，否則 Watcher 無法更新資料庫紀錄。

雷區四：Docker Compose 版本

本專案不相容 V1。必須使用 docker compose 而非 docker-compose。

雷區五：Host Key 變更

若重新部屬容器，SSH Host Key 會改變，需在 Fortigate 執行 execute ssh-known-hosts delete。

雷區六：rconfig 存儲目錄權限

RCONFIG_DATA_PATH 必須讓 Docker 使用者有寫入權限，否則備份檔無法被正確移動。

5. 日常維運常用指令

服務監控

# 服務狀態 
sudo docker compose ps
# 即時日誌 
sudo docker compose logs -f watcher

故障重啟

# 重新載入設定 
sudo docker compose up -d
# 拉取最新程式並編譯 
sudo git pull && sudo docker compose up -d --build
